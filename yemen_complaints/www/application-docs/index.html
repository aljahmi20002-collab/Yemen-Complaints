الوثيقة الشاملة للتطبيق

منصة اليمن للشكاوى والتظلمات — وثيقة تنفيذية ووظيفية وتشغيلية تغطي مكونات النظام، تدفق العمل، الذكاء الاصطناعي، التحقق من الهوية، وأدلة التشغيل الأساسية.

اسم التطبيق: yemen_complaints الإطار: Frappe Framework اللغة: العربية نوع الوثيقة: مرجع شامل + قابل للطباعة

1. مقدمة

منصة اليمن للشكاوى والتظلمات هي نظام إلكتروني متكامل لاستقبال الشكاوى والتظلمات من المواطنين اليمنيين داخل اليمن وخارجه، مع إمكانيات التحقق من الهوية، الإحالة، المتابعة، التقارير، المؤشرات، الطباعة، والإشعارات، إضافة إلى قدرات ذكاء اصطناعي مساعدة لموظفي الاستقبال والمعالجة.

المنصة مبنية على Frappe Framework ومهيأة للتوسع المؤسسي مع واجهات عربية احترافية وخط رسمي موحد.

2. أهداف النظام

الهدف الرئيسيتمكين المواطن اليمني من تقديم شكوى أو تظلم ومتابعته إلكترونياً من أي مكان في العالم.
التحققضمان التحقق من هوية مقدم الشكوى قبل الإرسال.
التشغيلتمكين الجهات المختصة من الفرز والإحالة والمتابعة بكفاءة.
التحليلتوفير تقارير تشغيلية ومؤشرات أداء ودعم قرار ذكي.

3. نطاق التطبيق

  • تقديم الشكاوى والتظلمات عبر Web Forms.
  • التحقق من الهوية عبر Email / SMS / WhatsApp / Telegram.
  • إدارة ملفات الشكاوى، الإحالات، التحديثات، والتقارير.
  • Workspaces، Number Cards، Dashboard Charts، وتقارير Script Reports.
  • تكامل AI مع ChatGPT وDeepSeek وGemini.
  • شاشة مستقلة للتحقق OTP وبيانات مرجعية للمحافظات والمديريات اليمنية.

6. تدفق العمل التشغيلي

  1. المواطن يفتح نموذج الشكوى أو التظلم.
  2. يملأ البيانات الأساسية ويختار قناة التحقق.
  3. يتم إرسال رمز OTP وتأكيد الهوية.
  4. تُنشأ الحالة في النظام.
  5. المستشار يراجع ويصنف ويشغّل المساعد الذكي عند الحاجة.
  6. تُحال الحالة إلى الجهة أو المسؤول المختص.
  7. تتم المعالجة والتحديثات والمتابعة ثم الحسم أو الإغلاق.

7. Workflow الرسمي

الحالات: New → Under Review → Assigned → In Progress → Waiting Citizen → Resolved / Rejected / Closed / Overdue
  • لا يسمح بالحسم أو الإغلاق بدون Resolution Summary.
  • لا يسمح بالانتقال إلى Assigned دون مسؤول أو إحالة.
  • التحولات مضبوطة حسب الدور، مع صلاحيات أوسع لمدير النظام.

  • SMS
  • WhatsApp
  • Telegram

المسارات

  • /verify-identity شاشة مستقلة وجميلة للتحقق OTP
  • دمج مباشر داخل Web Forms للشكوى والتظلم

المزايا

  • إرسال الرمز، تأكيده، إعادة الإرسال، عداد زمني، وسجل أحداث ومحاولات واضح.
  • تعليم الرمز كـ Used بعد استخدامه بنجاح مع شكوى حقيقية.
  • تقييد الإرسال حتى تصبح الحالة Verified.

19. الأمان والتشغيل

  • تقييد الوصول بالأدوار المناسبة.
  • منع المواطن من تغيير الحالة مباشرة.
  • منع استخدام OTP أكثر من مرة.
  • مراقبة AI Log وIdentity Verification records باستمرار.
  • حفظ مفاتيح API بصورة آمنة والاختبار أولاً على بيئة staging.

20. التوصيات المستقبلية

  • إضافة rate limiting وabuse protection على واجهات OTP وAI.
  • إضافة لوحة مراقبة لسجلات AI وOTP.
  • إضافة مراقبة تكلفة الذكاء الاصطناعي واستهلاك المزود.
  • ربط Telegram/WhatsApp/SMS بمزوّدات فعلية أو بوابة حكومية داخلية.
